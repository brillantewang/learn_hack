# Composer & Autoloading in Hack

## What is Composer?

Composer is PHP's package manager (like npm for Node or pip for Python). Hack inherited it because Hack was built on top of PHP/HHVM. There's no separate Hack package manager — Hack packages are published to the same registry (packagist.org) and use the same `composer.json` format.

Composer itself is written in PHP, so it must be installed and run with `php`, not `hhvm`. HHVM can't run the Composer installer.

## Our dependencies

Defined in `composer.json`:

- **`hhvm/hacktest`** — test framework (like pytest or jest). Provides the `HackTest` base class and test runner.
- **`facebook/fbexpect`** — assertion library. Provides `expect($actual)->toBeSame($expected)` syntax.
- **`hhvm/hhvm-autoload`** — Hack's autoloader. Scans source directories, builds a map of class/function → file, and registers it with HHVM so code can reference things without explicit imports.

All three are open-source Meta packages. They're marked as "abandoned" on packagist because Meta has moved on from open-source HHVM, but they still work fine.

## How autoloading works

Hack doesn't have `import` or `require` statements like Python/TypeScript. Instead:

1. **`hh_autoload.json`** tells the autoloader where to look for source files.
2. Running `hhvm vendor/hhvm/hhvm-autoload/bin/hh-autoload` (or triggered automatically by Composer's post-install hook) scans those directories and generates `vendor/autoload.hack`.
3. `vendor/autoload.hack` contains a literal map like:
   ```
   'unit2ex1\\high_risk_scores' => 'units/02_collections/ex01_basics.hack',
   ```
4. At runtime, when HHVM encounters an unknown class or function, it looks it up in this map, loads the file, and continues. This is a **runtime-level** mechanism built into HHVM — no Hack code explicitly "asks" the autoloader. It just happens.

## hh_autoload.json explained

```json
{
  "roots": ["units/"],
  "devRoots": ["tests/"],
  "includeVendor": true,
  "autoloadFilesBehavior": "parse"
}
```

- **`roots`** — directories containing Hack source files to scan recursively.
- **`devRoots`** — same, but for dev-only files (tests). Must exist on disk or the autoloader crashes.
- **`includeVendor`** — scan Hack files in `vendor/` packages. Uses smart scanning that skips PHP files. (Don't put `vendor/` in `roots` directly — it will try to parse Composer's PHP files as Hack and crash.)
- **`autoloadFilesBehavior`** — `"parse"` means only register definitions. `"exec"` would also execute top-level side effects (like `<<__EntryPoint>>` functions), which we don't want during autoloading.

## What's in vendor/

A mix of relevant and irrelevant files:

- **`vendor/composer/`** — PHP autoloader files. Irrelevant to Hack projects — these are for PHP's autoloading system.
- **`vendor/hhvm/hacktest/`** — actual `.hack` source files. Used by our tests.
- **`vendor/facebook/fbexpect/`** — actual `.hack` source files. Used by our tests.
- **`vendor/bin/`** — shell script wrappers generated by Composer. Each one finds and `exec`s the real Hack entry point in the package.

No PHP files in `vendor/` are relevant to Hack projects.

## How `vendor/bin/hacktest tests/` works

1. **`vendor/bin/hacktest`** — a shell script (`#!/usr/bin/env sh`) generated by Composer. Resolves the path to `vendor/hhvm/hacktest/bin/hacktest` and `exec`s it.
2. **`vendor/hhvm/hacktest/bin/hacktest`** — the real entry point (`#!/usr/bin/env hhvm`). HHVM starts here.
3. **Loads `vendor/autoload.hack`** — registers the autoload map with HHVM.
4. **Scans `tests/`** — finds `.hack` files containing classes that extend `HackTest`.
5. **Discovers test methods** — methods starting with `test`.
6. **Runs each test** — any reference to your exercise code (e.g., `Unit2Ex1\high_risk_scores`) triggers the autoloader, which loads the file on the fly.
7. **Outputs results** — `.` per pass, `F` per fail, then a summary.

## Setup gotchas we hit

- **HHVM can't install Composer** — use `php`, not `hhvm`, for the installer.
- **`allow-plugins` prompt** — Composer requires explicit opt-in for plugins that run code during install. `hhvm/hhvm-autoload` needs this. Configured in `composer.json` under `config.allow-plugins`.
- **`devRoots` directory must exist** — the autoloader crashes if `tests/` doesn't exist on disk.
- **Don't put `vendor/` in `roots`** — the autoloader can't parse PHP files. Use `includeVendor: true` instead.
- **`COMPOSER_ALLOW_SUPERUSER=1`** — suppresses Composer's warning about running as root (fine in a container).

## How this differs from Meta production

| Our setup | Meta production |
|---|---|
| Composer | Buck (internal build system) |
| `hh_autoload.json` | Buck handles autoloading |
| `hhvm file.hack` to run | Internal deployment pipeline |
| HackTest (open source) | HackTest (internal fork, similar API) |

The **Hack language** is identical. The tooling around it is completely different — you'll learn Meta's tooling on the job.
